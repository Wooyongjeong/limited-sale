# 1-3 회원·비밀번호·권한 상세 협의

상태: 사용자와 설계·정책·완료 기준을 확정하고 구현 시작을 지시했다. 이전 구현의 주 에이전트 독립 검증은 완료했고, 재리뷰에서 발견한 보완의 주 에이전트 확인은 대기 중이다. 1-4는 시작하지 않았다.

## 확정한 추가 결정

- Argon2id 초기 비용: 메모리 19MiB·반복 2·병렬도 1. 사용자가 로컬 측정 결과를 확인하고 선택했다. [측정 결과](01-3-argon2-measurement.md)를 따른다.
- 중복 이메일 가입: HTTP 409 / EMAIL_ALREADY_EXISTS로 명시한다. 사용자에게 수정할 입력을 명확히 안내하는 방식을 선택했으며, 이메일 가입 여부가 드러나는 점을 설명하고 합의했다. DB 유니크 제약으로 동시 가입도 하나만 생성되게 하고 나머지는 동일 오류로 변환한다.

## 닉네임 추가 요구와 확정 정책

- 회원 정보에 닉네임을 추가한다. 한글·영어·숫자·공백을 허용하며 정리 후 공백 포함 최대 12글자다.
- 앞뒤 공백을 제거하고 연속 공백을 하나로 정리한다. 영문 표기는 보존하고 중복 검사는 대소문자를 구분하지 않는다.
- 누락·빈 문자열·공백만 입력한 경우 접두어+접미어를 무작위 조합한다. 예: 발랄한 강아지.
- 모든 회원 닉네임은 유일하다. 직접 입력한 닉네임 중복은 HTTP 409로 응답한다. 자동 생성은 기존 이름과 충돌하면 뒤에 숫자를 붙인다. 예: 발랄한 강아지1.
- 동시 가입의 닉네임 충돌도 DB 유니크 제약으로 방어한다. 기존 Flyway 파일을 수정하지 않고 새 마이그레이션으로 반영한다.

## 추가 확정 계약

- 닉네임은 NFC 정규화 후 가–힣 완성형 한글, ASCII 영문 A–Z/a–z, 숫자 0–9, 일반 공백만 허용한다. 자모 단독 입력은 허용하지 않는다.
- 자동 생성의 숫자는 1부터 시작한다. 숫자까지 포함해 12글자를 넘으면 기본 이름을 자르지 않고 다른 접두·접미 조합을 생성한다.
- 회원가입 성공 응답은 이메일·닉네임·권한을 반환한다. 내부 회원 ID는 유지하되 이 응답에는 노출하지 않는다. 비밀번호·해시는 반환하지 않는다.

## 제안한 구현 범위와 완료 기준

회원가입 API, 닉네임 생성·중복 방어, Argon2id 비밀번호 해싱, USER/ADMIN 구분, 관리자 초기화 명령과 필요한 공개 회원 계약을 구현한다. 로그인·Redis 세션은 1-4 범위다. 닉네임 추가는 새 Flyway 마이그레이션으로 처리하며 기존 행이 있는 경우에도 유일하고 유효한 닉네임으로 이행해야 한다.

입력 경계·닉네임 정규화·비밀번호 검증, 이메일 및 닉네임 동시 중복 가입, 자동 생성 충돌, 관리자 초기화의 기존 ADMIN 무변경·기존 USER 거절을 검증한다. 실제 MySQL 통합 검증, Java 21 빌드와 패키지 경계 검사, diff 검사를 완료 기준으로 제시한다.

## 설계 검토와 선택

사용자가 구현 전에 설계 검토를 선택해 현재 MemberEntity와 기존 스키마·통합 테스트를 확인했다. 현재 회원 영속 매핑에는 닉네임이 없고 회원가입 업무 로직도 없다.

### 사용자 선택: 자동 생성 번호

조합별 별도 카운터 테이블과 가장 작은 빈 번호를 찾는 방식을 비교했다. 사용자는 후자를 선택했다. 숫자가 없는 기본 이름을 우선 사용하고 중복이면 1부터 가장 작은 빈 숫자를 찾는다. 동시 저장의 최종 판정은 DB 유니크 제약이며 충돌 후 새 트랜잭션에서 후보를 다시 찾는다. 닉네임 길이를 넘으면 다른 조합으로 전환한다.

### 제안 구조

- presentation: 가입 JSON 입력과 공통 응답 변환. 공개 가입의 역할 입력은 받지 않는다.
- domain: 정규화된 이메일·닉네임 값과 규칙, 회원·권한, 회원 저장소 및 해싱 계약. 프레임워크·JPA 의존성을 두지 않는다.
- application: 회원가입과 관리자 초기화 흐름을 조합한다. 관리자 초기화도 같은 닉네임 규칙을 사용한다. 기존 ADMIN 무변경·동일 이메일 USER 오류 정책을 유지한다.
- infrastructure: JPA 저장, 비밀번호 해싱, 무작위 후보 생성의 외부 기능을 구현한다. 표시 닉네임과 소문자 비교 키를 분리하고 비교 키의 DB 유니크 제약으로 중복을 방어한다.
- api: 향후 인증 어댑터가 사용할 회원 인증·조회 계약을 제공하되 해시를 노출하지 않는다. 필요 없는 빈 계약은 만들지 않는다.

### 가입 흐름

입력 정규화·검증 → 트랜잭션 밖에서 해싱·후보 생성 → 짧은 트랜잭션에서 USER 저장 → 이메일·닉네임·권한 반환.

자동 닉네임 충돌은 실패 트랜잭션을 종료한 뒤 새 트랜잭션에서 재시도한다. 해시는 재사용한다. 수동 닉네임 충돌과 이메일 충돌은 해당 409 오류로 응답하며 DB 장애를 중복 오류로 바꾸지 않는다.

사용자는 자동 닉네임 생성·저장 시도 최대 20회와 소진 시 HTTP 503 / NICKNAME_GENERATION_UNAVAILABLE 응답을 확정했다. 12글자 초과로 다른 조합을 고르는 경우도 상한에 포함한다. 실패 시 회원은 생성되지 않는다. 무한 반복과 부분 가입을 허용하지 않는다. 기존 회원이 있는 DB에서의 새 닉네임 마이그레이션 검증도 완료 기준에 추가한다.

## 구현과 워커 검증

- `POST /api/v1/members`는 이메일·비밀번호·선택 닉네임을 받고 USER의 이메일·닉네임·권한을 반환한다. 이메일과 닉네임 중복은 각각 `EMAIL_ALREADY_EXISTS`, `NICKNAME_ALREADY_EXISTS`, 자동 생성 소진은 `NICKNAME_GENERATION_UNAVAILABLE`이다. 검증 오류는 `INVALID_INPUT`과 field/reason 목록이다.
- `initAdmin` Gradle 명령은 환경변수로 입력받는 별도 프로세스다. 기존 ADMIN을 수정하지 않고 같은 이메일의 USER는 오류로 종료한다.
- V3 Java Flyway 마이그레이션은 기존 행의 ID를 41진법으로 변환해 허용된 문자 12자 이내의 유일한 닉네임을 부여하고 비교 키에 유니크 제약을 추가한다. 기존 비밀번호 해시·역할·참조를 유지한다. 적용된 기존 V1·V2 파일은 수정하지 않았다.
- 인코딩은 DB 트랜잭션 밖에서 수행한다. 수동 닉네임은 DB 충돌을 409로 변환한다. 자동 닉네임은 1부터 가장 작은 빈 번호를 찾고 충돌한 트랜잭션을 종료한 뒤 새 트랜잭션으로 최대 20회 시도한다.
- 독립 MySQL 8.4.7 Testcontainers에서 기존 회원이 있는 상태의 마이그레이션, 동시 이메일·닉네임 충돌, 자동 생성 충돌 후 재시도·20회 고갈·12자 경계, ADMIN 무변경·USER 거절, API 응답과 해시를 검증했다. 자동 생성 충돌 검사는 DB에 경쟁 행을 삽입해 유니크 충돌을 재현한다.
- 최초 워커 검증에서 Java 21 `./gradlew clean build`를 실행했다. 당시 단위·구조 테스트 6개와 MySQL 통합 테스트 16개가 성공했고 실패·건너뜀은 0개였다. 주 에이전트 검증은 별개다.
- 별도 임시 MySQL 8.4.7 컨테이너에서 `./gradlew initAdmin`을 동일 입력으로 두 번 실행하고 ADMIN 행이 한 개임을 확인했다. 테스트 컨테이너는 종료했다.

기존 스키마의 Flyway 테스트와 Mock PG 테스트 의존성이 같은 클래스패스에 모이면 `db/migration`의 V1·V2가 겹친다. 통합 테스트에서는 판매 SQL의 파일 경로와 V3 Java 마이그레이션 경로를 명시해 각각의 스키마만 적용했다. 운영 앱에서는 판매 SQL 경로와 V3 경로를 사용한다.

MySQL DDL은 원자적인 단일 트랜잭션이 아니다. V3 적용 중 프로세스가 중단되면 Flyway 실패 이력과 실제 컬럼 상태를 확인해 복구해야 하며, 자동 재실행만으로 부분 적용 복구가 보장되지는 않는다.

## 독립 검증 중 발견한 보완

기존 자동 닉네임 탐색은 번호마다 별도 SQL을 호출했다. 이를 닉네임 비교 키의 인덱스를 사용할 수 있는 범위 조건으로 숫자 접미사의 첫 빈 번호를 찾는 단일 SQL로 변경했다. 기본 이름이 비어 있으면 기본 이름을 사용하고, 숫자 0이나 앞에 0이 붙은 접미사는 자동 생성 번호로 취급하지 않는다. 동시 충돌 뒤에는 현재의 가장 작은 빈 번호를 다시 찾기 위해 실패 트랜잭션이 끝난 후 한 번 더 조회한다. 조회와 저장 시도는 기존처럼 최대 20회다.

비밀번호 해싱 계약은 `member.domain.PasswordHasher`, Argon2id 구현은 `member.infrastructure.security`가 소유한다. 해싱은 삽입 트랜잭션 밖에서 한 번 수행하고 충돌 재시도에서도 해시를 재사용한다.

기존 회원의 ID는 signed long에 `2^63`을 더한 0 이상 `2^64 - 1` 이하의 값으로 일대일 변환한다. 허용된 41개 문자로 표현하면 `41^12 = 22563490300366186081`이 `2^64 = 18446744073709551616`보다 크므로 모든 ID가 12자 안에 들어간다. 단위 테스트가 최솟값·최댓값과 인접값을 역변환해 유일성을 확인하고, 별도 MySQL 스키마에서 양 끝값의 실제 마이그레이션과 기존 컬럼 보존을 확인한다. 기존 주문의 회원 참조도 확인한다.

기본 이름과 1~1,000의 숫자 접미사 중 하나를 제외한 MySQL 데이터에서 중간 빈 번호, 대소문자 보존 및 선행 0 접미사의 구분을 확인했다. JDBC 호출 계측은 한 가입에서 후보 조회 SQL이 1회 실행됐음을 확인한다. 동시 충돌이 20번이면 조회와 저장을 각각 20번으로 제한하고 해시는 한 번만 계산하는지도 검증한다.

보완 후 Homebrew Java 21로 `./gradlew clean build --console=plain`을 실행했다. 단위·구조 테스트 7개와 실제 MySQL 통합 테스트 18개가 성공했고 실패·건너뜀은 0개다. `git diff --check`와 미추적 파일의 공백 검사를 통과했다. 주 에이전트의 보완 후 독립 검증 결과는 아래에 기록한다.

## 주 에이전트 최종 독립 검증

보완 후 소스를 직접 검토하고 Homebrew Java 21로 `./gradlew clean build --console=plain`을 재실행했다. `BUILD SUCCESSFUL in 47s`, 작업 17개가 모두 실행됐다. XML 결과에서 단위·구조 7개, 실제 MySQL 통합 18개, 합계 25개 성공과 실패·오류·건너뜀 각각 0개를 확인했다. 가입 HTTP→DB 저장·해시 확인, 이메일·닉네임 동시 중복, 자동 생성의 빈 번호·경계·고갈, 트랜잭션 밖 해싱 1회, 기존 회원 마이그레이션과 주문 참조 보존을 포함한다.

`git diff --check`와 추가 파일 공백 검사를 통과했다. 커밋·푸시·PR은 수행하지 않았다. MySQL DDL 부분 적용 시 수동 복구가 필요할 수 있는 제약은 위와 같다. 다음 1-4는 별도 협의 후 진행한다.

## 재리뷰 보완과 독립 검증 완료

- 주 에이전트가 독립 MockMvc 재현에서 `Content-Type: text/plain` 요청이 415가 아닌 500으로 처리되는 문제를 발견했다. 또 `Accept: application/xml` 요청은 응답 직렬화가 실패한 뒤 406이 반환돼 회원가입 서비스가 이미 실행될 수 있었다.
- 워커가 먼저 회귀 테스트를 실행해 3개 중 2개가 실패함을 확인했다. 회원가입의 응답 형식을 JSON으로 명시해 호환되지 않는 Accept를 서비스 호출 전에 406으로 거절하고, 지원하지 않는 요청 본문은 415와 `UNSUPPORTED_MEDIA_TYPE` 공통 응답을 반환하도록 수정했다. 406은 클라이언트가 JSON을 받아들이지 않으므로 본문 없이 반환한다.
- 다른 Spring 4xx 예외는 포괄 오류 처리기에서 500으로 변환하지 않고 프레임워크에 넘긴다. 예상하지 못한 서버 오류는 500과 일반 메시지를 반환한다. 워커 테스트에서 서비스 미호출, 415 응답, 406 빈 본문, 다른 4xx 상태 유지와 내부 메시지 비노출을 확인한다.
- README는 전역 등록되지 않은 Homebrew Java 21 경로를 현재 셸에서 지정하고 `java -version`으로 확인하도록 바꿨다. 기존 `/usr/libexec/java_home -v 21`은 이 환경에서 Java 17을 선택했다.
