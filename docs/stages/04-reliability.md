# 4단계: 장애 검증과 포트폴리오 정리

작성일: 2026-11-10

[전체 기획](../project-plan.md) · [구조 설계](../architecture.md)

## 상태

4-1 정책 확정(2026-11-25). 4-2(넘어온 과제 수정) 착수 전. 소단계: 4-1 정책 → 4-2 넘어온 과제 수정 → 4-3 장애 실험 → 4-4 포트폴리오 정리.

## 확정한 방향

기능 수보다 동시성·정합성·장애 복구를 재현하고 검증한 근거를 포트폴리오에 남긴다. 개발자는 설계 판단과 실험 해석을 맡고, AI가 만든 구현과 실험 도구를 검증한다.

## 구현·정리할 사항

- API 2개와 MySQL·Redis·Kafka·Mock PG의 전체 흐름에서 장애를 재현한다.
- Redis·Kafka 중단, 소비자 강제 종료, DB 저장 실패, 결제 응답 유실과 재시도를 실험한다.
- 재고·구매 한도·주문·결제·접수 상태를 대조하고 복구 절차를 정리한다.
- 재현 명령, 대시보드, 실행 환경, 원본 결과와 분석을 남긴다.
- 선택한 설계·대안·한계, AI 제안에서 발견한 문제와 수정 근거를 기록한다.

### 시나리오 초안(4-3에서 실행 전 기대 결과를 확정한다)

| # | 시나리오 | 경로 | 주입 | 예상 동작(초안) |
|---|---|---|---|---|
| S1 | Redis 중단 | v1·v2 | 부하 중 Redis 정지 → 재기동 | 장애 중 세션이 필요한 요청은 오류로 응답하고, 캐시·요청 제한·품절 표시는 우회된다(2-5 정책). 4-2 수정 뒤 이미 커밋된 주문은 성공으로 응답된다. 복구 뒤 재시도로 모두 최종 상태가 된다 |
| S2 | Kafka 중단 | v2 | 부하 중 브로커 정지 → 재기동 | 접수는 계속 받고, 발행·소비는 재기동 뒤 이어진다(3-8 ①과 같다) |
| S3 | 소비자 강제 종료 | v2 | 판매 JVM 하나 SIGKILL → 재기동 | 남은 인스턴스가 발행을 이어받는다. 재기동 뒤 파티션을 다시 나누고 중복 주문은 0이다(3-8 ②와 같다) |
| S4 | 소비자 강제 종료 후 재기동 안 함 | v2 | SIGKILL만 | 4-2에서 줄인 세션 시간 초과 안에 남은 인스턴스가 파티션을 이어받는다. 인계 시간을 잰다 |
| S5 | DB 저장 실패 | v1·v2 | 부하 중 쓰기 실패 주입(방식은 4-3에서 정함) | v1은 그 요청이 실패하고 같은 키로 재시도하면 성공한다. v2는 3-6 규칙(일시 오류 재시도, 30초 초과면 `PROCESSING_FAILED`)을 따른다 |
| S6 | MySQL 실제 정지 | v1·v2 | MySQL 정지 → 재기동 | 모든 경로가 오류로 응답한다. v2 소비자는 실패를 저장할 수 없으므로 DB가 돌아올 때까지 재시도하고(3-6 #4), 돌아오면 정상 처리한다 |
| S7 | 결제 응답 유실 후 재시도 | v2(결제는 v1 API) | Mock PG `RESPONSE_LOSS` | 결제 요청이 시간 초과되고, 재요청이나 자동 복구로 PG 결과를 조회해 확정한다. 중복 결제는 0이다(1단계 정책) |
| S8 | Redis·Kafka 동시 중단 | v2 | 둘을 같은 구간에 정지 | S1과 S2의 기대 결과를 합친 것과 같고, 서로의 복구를 막지 않는다 |
| S9 | 판매 앱 순차 재시작 | v2 | 인스턴스 하나씩 SIGTERM → 재기동 | 로드 밸런서 뒤에서 요청은 남은 인스턴스로 가고(재시도 포함), 발행자·소비자는 교대한다. 중복 주문은 0이다 |

## 검증 기준

실험 전에 예상 결과와 검증 기한을 정한다. 복구 후 초과 판매·구매 한도 초과·중복 주문·중복 결제가 없어야 한다. 모든 접수 요청은 최종 상태와 대조하고, 처리 실패도 원인을 보고한다. 모두 실패하거나 미완료 요청을 제외한 결과를 성공으로 설명하지 않는다.

## 앞 단계에서 넘어온 후속 과제

- 2-5: Redis가 멈추는 순간 처리 중이던 요청은 성공 응답을 쓰는 중에 Spring Session 저장이 실패한다. 이미 커밋된 주문·결제의 응답이 깨지거나 "주문 처리 실패" ERROR가 남는다. 같은 요청 키 재시도로 정합성은 지켜진다. 응답 전 세션 저장, 오류 분류 등 설계를 정한다. 근거는 [2-5 실험 결과](02-redis.md#2-5-실험-결과와-검증)다.
- 2-5: 동시성 200에서 Caddy가 판매 인스턴스 연결에 실패한 502(원인 미확정).
