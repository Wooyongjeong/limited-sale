# 1-7 주문·Mock PG 결제

상태: [1-7-1](01-7-1-order-reservation.md) 구현·검증·위키 완료. 1-7-2 이후는 정책 확인과 별도 시작 지시가 필요하다.

기존 [주문·결제 계약](01-contracts.md)과 [1단계 정책](01-mysql-order.md)을 따른다. 사용자와 소단계별 정책을 확정한 뒤 각각 구현 시작 지시를 받는다. 1-6의 주 에이전트 직접 구현은 해당 단계만의 예외다. 이후에는 Terra high 구현 → 주 에이전트 리뷰·검증 → 문제 해결까지 보완 반복 → 위키 갱신·검증으로 진행한다.

## 세부 단위

| 단위 | 범위 | 완료 기준 |
|---|---|---|
| 1-7-1 | 주문 생성·재고와 사용자 한도 점유·요청 결과 멱등성·최소 상세 조회 | 정상·업무 거절·중복·동시 요청에도 결과와 수량이 일치하고 주문·점유·결제 준비가 원자적으로 기록됨 |
| 1-7-2 | Mock PG HTTP 결제·조회·종료 및 재현 시나리오 | 영속 키별 결과·금액 검증, 종료 후 늦은 결제 차단, 지연·응답 유실 재현과 재시작 보존 |
| 1-7-3 | 판매 서버 PG 연동·결제 요청·주문 확정과 점유 해제 | HTTP는 DB 잠금 밖에서 수행하고 중복 결과가 중복 확정·해제를 만들지 않음 |
| 1-7-4 | DB 기반 복구·작업 임대·재시작 | 미완료 작업이 재시작 후 수렴하고 모르는 결과의 점유를 임의 해제하지 않음 |
| 1-7-5 | 전체 동시성·장애 회귀 검증 | 요청·결제·점유 기록을 대조해 장애와 경쟁 중에도 수량·금액·최종 상태의 정합성을 검증함 |

각 구현 단위에서도 필요한 동시성·회귀 테스트를 바로 실행한다. 마지막 단위까지 테스트를 미루지 않는다. 1-8은 내 주문 목록과 조회 기능 보강을 다루며, 1-7-1에서는 생성 결과를 확인할 최소 상세 조회만 선행한다.
